## 분석 정의
| 항목 | 결정 |
|---|---|
| 지표 | 노출보정 **시간층화** 상대위험 (공간 gradient 아님 — 한 구역 내 기상범주 간 비교) |
| 기준선 | **맑음 대비** RR = (사고/노출시간)ᵇⁱ/ᵉ ÷ (사고/노출시간)ᵐᵃˡᵍᵘᵐ. "비/눈이면 맑을 때보다 N배" |
| 기상 범주 | 눈: 신적설>0 or (강수>0 & 기온≤0) / 비: 강수≥0.1mm / 맑음: 그 외 / 데이터없음: 결측(±1h tolerance 실패). 눈>비 우선. 분자·분모 동일 규칙 |
| 색상 구간 | 분위수(quantile) 5단계 choropleth. 소표본 셀은 반투명·점선 (**구현 임계: 사고건수<10 또는 CI 상한/하한비>3** — 최초 n≤1 안은 눈 n=4 셀도 '신뢰가능'으로 보이게 해 상향 조정) |
| `데이터없음` | 상대위험 계산 제외 + 지도 회색, 결측 비율 문서 명시 |
| 신뢰구간 | **Byar 포아송 근사 + 로그척도 MOVER 결합** (rate ratio 구간). 분자·기준선이 0인 셀은 degenerate 처리. 다중비교(25구×2범주)는 BH(FDR) 보정치를 참고용 병기 |

## 데이터 소스 변경 (2026-07-14 실측 반영)
- **개별 사망사고 CSV (data.go.kr 15070340) 파기됨** — 페이지 자체가 열리지 않음, 재배포 중단. 집계 통계본(15070282/297 등)은 기상 분해가 없어 대체 불가.
- 대체 소스 = **TAAS GIS "사고분석 → 지역별" 엑셀** (`taas.koroad.or.kr/gis`, 조건검색→목록보기→엑셀). **좌표·발생시각 없음, 시군구 + 기상상태까지** 제공. 연도별 전량이 한 파일로 받아짐(구별 분할 불필요).
- **확정 변경 사항**:
  - 분석단위: 다발지역 폴리곤 → **자치구 25개** (좌표 부재로 강제 — 플랜 Phase0 게이트의 시군구 승격과 일치). 다발지역은 선택적 오버레이로 강등.
  - 기상 분자: ASOS 시간매칭 불필요 → 사고 데이터에 기록된 **경찰기록 기상상태** 직접 사용. ASOS는 **노출시간(분모) 전용**.
  - 심각도: **사망 + 중상** 확정. (사망만은 눈 10년 14건→구별 불가. 사망+중상이면 눈 연 21건·10년 ~200건으로 구별 지도 성립.) 지표를 **"심각(사망·중상)사고 위험"** 으로 재정의.
  - 기상범주: **맑음(맑음+흐림 비강수 통합) / 비 / 눈 / 기타(안개·결측=상대위험 제외)**. 눈은 소표본 경고 스타일.
  - 한계 추가: 사고 기상분류(경찰 정성기록)와 노출 분류(ASOS 정량관측)가 다른 출처 → 문서 명시.
- 데이터: `data/raw/accidents/사고분석-YYYY.xlsx` (심각도별 하위 폴더 없이 평면 배치 — 사망+중상 조건으로만 받는다). 로더: `src/analysis/accidents.py`.
  - 심각도가 섞이는 사고를 막기 위해 `load_accidents()` 가 `사고내용` 분포를 검사해 범위 밖 라벨을 경고한다(`check_severity`).

## 분석 기간 확장 2014~2023 → 2007~2025 (2026-07-22)

| 항목 | 결정 |
|---|---|
| 분석 기간 | **2007~2025 (19년, 228개월)**. TAAS에 2007년부터 제공되는 것을 확인 |
| 확장 근거 | 이 지표의 병목은 **눈 표본**이다. 10년 기준 눈 사고 325건에 25개 구 중 **16개가 소표본 경고**라 지도 상당 부분이 반투명으로 렌더됐다. 강남구 단독 실측(19년 눈 92건)으로 미루어 전 구 확장 시 눈 표본이 약 3배가 되어 소표본 셀이 실질적으로 줄어든다 |
| 라벨 일관성 | **실측 확인** — 19년 전 연도의 `기상상태` 라벨이 `맑음/흐림/비/눈/안개/기타` 6종으로 동일. 우려했던 2017년경 라벨 개편의 영향 없음(`_WEATHER_MAP` 이 전부 커버, 기타 비율 연 0.4~5.2%) |
| `발생년월` 포맷 | 19년 내내 `YYYY년 M월` 단일 형태, 파싱 불일치 0건 |
| ASOS 수집 범위 | `.env` 의 `START_YEAR=2007`, `END_YEAR=2025` 로 사고 기간과 **동일하게** 맞춘다 |

### 기간 정합성 가드 (같은 날 추가)
- 상대위험은 `사고건수 ÷ 노출시간` 이라 분자·분모 기간이 다르면 **에러 없이 틀린 값**이 나온다. `exposure.load_weather()` 는 디렉토리의 모든 파일을 읽을 뿐 기간 필터가 없어, 파일 구성이 곧 분모 기간이 된다.
- `pipeline.check_period_alignment()` 가 사고 발생월 구간과 ASOS 관측월을 **월 단위**로 대조해 결손(분모 부족)·과대(기간 밖 노출)를 찾고, 어긋나면 산출물을 건드리기 전에 `SystemExit(1)` 로 중단한다.
- 연 단위가 아니라 월 단위로 판정한다 — 연 단위면 마지막 해가 일부만 수집된 경우를 놓친다.
