## 2. 데이터 소스

### 2.1. 교통사고 데이터 (분자)

**도로교통공단 교통사고분석시스템 (TAAS)**

| 속성 | 값 |
|---|---|
| **출처** | 교통사고분석시스템 GIS 조회 https://taas.koroad.or.kr/gis |
| **공공데이터포털 등재** | 데이터셋 ID `15075668` (교통사고 GIS정보) |
| **이용허락** | 출처표시(CC BY) |
| **저작자** | 도로교통공단 |
| **데이터 형식** | Excel (.xlsx) — 연도별 다운로드 |

**수집 조건:**
- **지역**: 서울특별시 / **시군구 = 전체 25개 구** (특정 구로 두면 그 구만 받아진다)
- **심각도**: **사망 + 중상** (사망만은 표본 부족 → 눈 사고 10년 14건으로 구별 지도 불가능)
- **기간**: 2007~2025 각 연도별 (총 19개 파일)
- **선택 방법**: 조건검색 → 목록보기 → 엑셀 다운로드

**데이터 스키마:**
- 발생년월 — 한글 표기 `YYYY년 M월` (예: `2023년 1월`). 2007~2025 전 연도 동일하며
  `accidents.accident_months()` 가 이 형태만 파싱한다
- 시군구 (자치구명, 예: "중구", "영등포구")
- 기상상태 (경찰 기록값: "맑음", "흐림", "비", "눈", "안개" 등)
- 사고유형, 사망·중상·경상·부상신고자수 등

> **주의**: 발생 시각(시 0~23)과 위경도는 **미포함**. 이로 인해 분석 단위가 자치구(시군구)로 확정됨. 사고 기상분류는 경찰 정성 기록값을 사용(ASOS 정량 관측과 출처 이원화).

**저장 위치:**
```
data/raw/accidents/사고분석-YYYY.xlsx   (예: 2023년 = 사고분석-2023.xlsx)
```

**규모:** 19년 누적. ⏳ **재수집 진행 중이라 확정 건수 미정** — 2026-07-22 기준 이전 창(2014~2023,
25개 구)의 실측은 3범주 합 79,325건이었다. 새 창의 수치는 재수집 후 `python -m src.analysis.pipeline`
실행 결과로 갱신한다. 기타(안개 등)는 RR 계산에서 제외된다.

범주별: 맑음 156,438h(93.92%) / 비 9,644h(5.79%) / 눈 477h(0.29%).

## 4. 재현 절차

### 4.1. 필수 구성 요소

1. **Python 3.8+** 및 필수 라이브러리 (`requirements.txt`)
2. **공공데이터포털 인증키** (`.env` 파일)
3. **TAAS 사고분석 엑셀 파일** (수동 다운로드)

### 4.2. 단계별 재현

#### Step 1: 환경 준비

```bash
# 저장소 클론
git clone https://github.com/eunkyo3/weather-crash-risk.git
cd weather-crash-risk

# Python 가상환경 생성
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

# 의존성 설치
pip install -r requirements.txt
```

#### Step 2: 인증키 설정

```bash
# .env 파일 생성
cp .env.example .env

# .env 에서 다음 항목 입력:
# DATA_GO_KR_SERVICE_KEY=<공공데이터포털_디코딩_인증키>
```

**인증키 발급 방법:**
1. https://www.data.go.kr 로그인
2. 마이페이지 → 활용신청 기관 목록 확인
3. 「기상청_지상(종관, ASOS) 시간자료 조회서비스」(15057210) 활용신청
4. 승인 후 인증키 복사

#### Step 3: 사고 데이터 수집 (수동)

1. TAAS GIS 접속: https://taas.koroad.or.kr/gis
2. 조건 설정:
   - 도시: 서울특별시 / **시군구: 전체**
   - 심각도: 사망 + 중상
   - 연도: 2007~2025 (각각 다운로드, 19회)
3. 목록보기 → 엑셀 다운로드
4. 파일 저장: `data/raw/accidents/사고분석-YYYY.xlsx`

**다운로드 후 폴더 구조:**
```
data/raw/accidents/
├── 사고분석-2007.xlsx
├── 사고분석-2008.xlsx
├── ...
└── 사고분석-2025.xlsx
```

#### Step 4: 기상 데이터 수집 (자동)

```bash
# ASOS 시간자료 수집 및 저장
python -m src.collect.fetch_weather
# → data/raw/weather/asos_108_YYYYMM.json 생성
```

> ⚠️ **`.env` 의 `START_YEAR`/`END_YEAR` 를 사고 데이터 기간과 반드시 같게 맞춘다.** 이 값이
> ASOS 수집 범위를 결정하고, 수집된 파일 구성이 곧 상대위험의 **분모 기간**이 된다.
> 기간이 어긋나면 사고율이 왜곡되지만 에러는 나지 않으므로, `pipeline` 이 실행 초반에
> 월 단위로 대조해 중단시킨다(§7.1 "기간 정합성"). 수집이 중간에 끊겼다면 같은 명령을
> 다시 실행하면 되며, 이미 받은 월은 그대로 두고 누락분만 채우면 된다.

#### Step 4-1: 자치구 경계 확인 (조치 불필요)

`data/raw/boundaries/seoul_gu.geojson` 은 저장소에 포함되어 있다. 존재 여부만 확인한다:

```bash
python -c "import json;print(len(json.load(open('data/raw/boundaries/seoul_gu.geojson',encoding='utf-8'))['features']),'개 자치구')"
# → 25 개 자치구
```

없다면(실수로 삭제 등) `data/README.md` 3절의 `curl` 명령으로 재취득한다.

#### Step 5: 분석 및 대시보드 생성

```bash
# 데이터 전처리 → 상대위험 산출 → 대시보드 생성
python -m src.analysis.pipeline
# → outputs/dashboard.html 생성
# → data/processed/zone_weather_risk.csv 생성
```

#### Step 6: 대시보드 확인

**로컬 실행:**
```bash
python -m src.serve
# → http://localhost:8000 에서 대시보드 접속
```

**또는 Docker:**
```bash
docker compose up --build
# → http://localhost:8000 에서 접속
# 중지: Ctrl+C 또는 docker compose down
```

## 5. 데이터 명세

### 5.1. 최종 분석 테이블: `zone_weather_risk.csv`

인코딩 `utf-8-sig`(엑셀 호환), **75행** = 자치구 25 × 기상범주 3. 컬럼명은 한글 그대로다
(발표·보고서에 그대로 싣기 위함).

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `구` | str | 자치구명 (예: "강동구") |
| `기상범주` | str | `맑음` / `비` / `눈` — **기타(안개·결측)는 RR 계산 대상이 아니라 이 파일에 없다** |
| `사고건수` | int | 해당 자치구×기상의 사고건수 (= 표본수 n) |
| `노출시간` | int | 해당 기상의 지속 시간수 (ASOS 108 기준, 전 자치구 공통) |
| `사고율_시간당` | float | 사고건수 ÷ 노출시간 |
| `상대위험` | float | RR = 사고율 ÷ 같은 구의 맑음 사고율. 맑음 행은 정의상 1.0 |
| `CI하한` | float | 95% 신뢰구간 하한 (Byar+MOVER). 맑음 행은 1.0, degenerate 셀은 빈 값 |
| `CI상한` | float | 95% 신뢰구간 상한 (동일) |
| `소표본경고` | bool | 사고건수<10 또는 CI 상한/하한비>3 이면 True (맑음 행은 항상 False) |

**실제 예시** (강동구, 커밋된 파일에서 발췌 — ⏳ **이전 창 2014~2023 산출물**이다. 2007~2025 재수집 후 갱신된다):
```
구,기상범주,사고건수,노출시간,사고율_시간당,상대위험,CI하한,CI상한,소표본경고
강동구,눈,13,194,0.06701030927835051,1.9131258187617475,1.0165904902332443,3.2758439319745665,True
강동구,맑음,2896,82680,0.03502660861151427,1.0,1.0,1.0,False
강동구,비,191,4774,0.04000837871805614,1.1422281603621829,0.9815948050421325,1.322402184205023,False
```

> 맑음 행의 CI가 `1.0, 1.0` 인 것은 오류가 아니라 **기준선이라 정의상 RR=1**이기 때문이다
> (`src/analysis/risk.py`). 기준선에 신뢰구간을 부여하지 않는다.

## 6. 한계 및 주의사항

### 6.1. 공간 해상도 제약
- 사고 데이터에 위경도 미포함 → 분석 단위 = 자치구(시군구)
- 다발지역 폴리곤 레벨 분석 불가능
- 자치구 내부의 지역별 위험 편차를 포착하지 못함

### 6.2. 기상 분류 이원화
- **사고 기상**: 경찰 정성 기록(TAAS) — 넓은 정의 (예: 눈은 강설부터 노면 결빙까지)
- **노출 기상**: ASOS 정량 관측 — 좁은 정의 (예: 신적설 > 0)
- **결과**: 눈 상대위험이 상향 편향될 수 있음 (분모 과소집계)

### 6.3. 노출편향 (Traffic Volume Bias)

> **문제**: 통행량이 보정되지 않음. 비나 눈 날씨에는 도로 통행량 자체가 감소하므로, 표면상 상대위험이 증가한 것으로 보여도 **실제는 통행량 감소에 의한 착시**일 수 있음.
>
> **현재 대응**: 노출시간으로 정규화하여 부분적으로 완화하나, 완전한 보정은 **미구현**.
>
> **향후과제**: 서울시 도로 교통량 데이터(시간대별·기상별)를 추가 입수하여 민감도 분석 실시. 예: "기상별 통행량 정규화 후 상대위험 재산출" → 위험이 얼마나 감소하는지 확인.

### 6.4. 소표본 경고
- 눈 사고: 자치구별 표본 매우 적음 (구별 최소 4건대)
- 자치구별 사고건수 < 10 또는 신뢰구간 과대 셀은 지도에서 경고 스타일(반투명) 표시
- 점추정(RR)이 아니라 신뢰구간과 함께 해석 필수

### 6.5. 발생시각 부재
- TAAS 데이터는 **발생년월(월 단위)** 까지만 제공하며 발생 시각(시 0~23)도, 일자도 없다
- 따라서 사고를 ASOS 관측시각과 **매칭하지 않는다** — 사고의 기상범주는 데이터에 기록된
  경찰 기상상태 라벨을 그대로 쓰고, ASOS는 노출시간(분모) 산출에만 쓴다
- 초기 설계의 "사고 시각 ±1h tolerance 기상 매칭"은 구현 불가능하며, 이 이원화가
  6.2의 편향 원인이다

## 7. 검증 및 QA

### 7.1. 데이터 무결성 검증

`python -m src.analysis.pipeline` 이 실행 중 **실제로 수행하는** 검사는 다음과 같다.
실패 시 동작이 검사마다 다르다 — **AC7 세 항목과 산출물 존재만 `SystemExit(1)` 로 중단**시키고,
커버리지·심각도·중복은 경고만 출력하며(데이터 품질 문제로 파이프라인을 죽이지 않되 사용자가
반드시 보게 한다), 오프라인 보장은 `RuntimeError` 를 던진다.

| 검사 | 위치 | 통과 조건 | 실패 시 |
|---|---|---|---|
| ASOS 커버리지 | `weather_coverage()` | 관측시간 / 기대시간 ≥ 0.8 | 경고 출력, 계속 진행 |
| **월별 결손** | `exposure.short_months()` | 각 달의 관측시간이 그 달 기대치의 90% 이상 | 경고 출력, 계속 진행 |
| **기간 정합성** | `pipeline.check_period_alignment()` | 사고 발생월 구간과 ASOS 관측월이 **월 단위로 일치** (결손·과대 0개월) | **`SystemExit(1)`** (산출물 미갱신) |
| **사고 구간 공백** | `pipeline.check_period_alignment()` | 사고 구간 안에 사고 0건인 달이 없음 | 경고 출력 (0건 달은 통계적으로 정상이나 파일 누락 신호) |
| 심각도 혼입 | `accidents.check_severity()` | `사고내용` 이 사망·중상 라벨만 포함 | 경고 출력, 계속 진행 |
| 구분번호 중복 | `accidents.load_accidents()` | 중복 없음 | 중복 제거 후 건수 보고, 계속 진행 |
| 레이어 공백 (AC7) | `pipeline.verify()` | 각 기상범주에 사고건수>0 인 구가 3개 이상 | **`SystemExit(1)`** |
| 범주 간 값 변화 (AC7) | `pipeline.verify()` | 비 vs 눈 RR이 다른 구가 3개 이상 | **`SystemExit(1)`** |
| 유의 상승 (AC7) | `pipeline.verify()` | CI하한>1 인 구가 3개 이상 (+ BH/FDR 보정치 병기) | **`SystemExit(1)`** |
| 산출물 존재 | `pipeline.verify()` | CSV·대시보드·경계 GeoJSON 파일 존재 | **`SystemExit(1)`** |
| 오프라인 보장 | `dashboard._save_atomic()` | 저장된 HTML에 외부 `script src`/`link href` 0건 | **`RuntimeError`** (기존 산출물은 보존) |

### 7.2. 수치 재현 방법

분석을 재현하려면:

1. 위 Step 1~5를 순차 실행
2. `data/processed/zone_weather_risk.csv` 생성 확인
3. 주요 지표 비교:

**분모(노출) — 2007~2025 실측 확정** (재현 시 이 값과 일치해야 한다):

| 지표 | 값 |
|---|---|
| 관측 기간 | 2007-01-01 00:00 ~ 2025-12-31 23:00 (228개월) |
| 노출시간 합 | **166,559시간** — 맑음 156,438 / 비 9,644 / 눈 477 |
| 커버리지 | 기대 166,560h(6,940일 × 24h) 대비 **100.00%** (결측 1시간) |

**분자(사고) — ⏳ 재수집 진행 중, 확정 전**

TAAS 재다운로드(시군구=전체, 2007~2025)가 끝나면 아래를 채운다. 그전까지
`data/processed/zone_weather_risk.csv` 와 `outputs/dashboard.html` 은 **이전 창(2014~2023)의
산출물**이므로 새 기간의 재현 대조에 쓸 수 없다.

| 지표 | 이전 창(2014~2023) 실측 | 2007~2025 |
|---|---|---|
| 행 수 | 75행 (자치구 25 × 기상범주 3) | 동일 예상 |
| 사고건수 합 | 79,325건 — 맑음 73,855 / 비 5,145 / 눈 325 | 재수집 후 확정 |
| 사고 데이터 기간 | 2014-01-01 ~ 2023-12-31 | 2007-01 ~ 2025-12 |
| 소표본 경고 셀 | 눈 16개 구 / 비 0 / 맑음 0 | 재수집 후 확정 (감소 예상) |

> 재현 결과가 다르면 TAAS 다운로드 조건(**시군구=전체**, 심각도=사망+중상, 연도 범위)을
> 먼저 확인한다. 시군구를 특정 구로 두면 그 구만 받아져 건수가 1/25 수준으로 줄어든다.
